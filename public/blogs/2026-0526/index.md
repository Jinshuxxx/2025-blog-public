# RabbitMQ

## 1. RabbitMQ 基础模式

### 1.1 简单模式 Simple

- 生产者直接向队列发送消息
- 消费者监听指定队列消费消息
- 可不经过自定义交换机，通常使用默认交换机
- Spring 中可使用 `RabbitTemplate` 发送消息
- 消费端可用 `@RabbitListener(queues = "...")` 监听队列

### 1.2 工作模式 Work Queue

- 一个队列可以绑定多个消费者
- 消息按轮询方式分发给不同消费者
- 每条消息只会被一个消费者消费一次
- 适合任务分发、异步削峰场景

### 1.3 扇出模式 Fanout

- 使用 `Fanout Exchange`
- 消息会复制并发送到所有绑定队列
- 一个生产者的消息可被多个消费者接收
- 交换机负责转发，队列负责存储消息

---

## 2. 交换机类型与路由规则

### 2.1 Direct 模式

- 根据 `routing key` 精确匹配投递消息
- 队列通过 `binding key` 与交换机关联
- 只有 `routing key` 匹配的队列才能收到消息
- 未匹配的消息不会进入队列，可能直接丢失

### 2.2 Topic 模式

- 基于通配符的 `routing key` 模糊匹配
- `*` 匹配一个单词，必须存在
- `#` 匹配零个或多个单词
- 适合灵活的业务分类路由

### 2.3 路由失败场景

- 交换机名称错误
- `routing key` 错误
- 队列未绑定
- 绑定关系错误
- 交换机不存储消息，只负责路由

---

## 3. 队列与交换机基础配置

### 3.1 队列参数

- `durable`：是否持久化
- `exclusive`：是否独占
- `autoDelete`：是否自动删除

### 3.2 概念

- 交换机负责接收并转发消息
- 队列负责存储消息
- 消费成功依赖以下配置均正确：
  - 交换机
  - 队列
  - 路由键
  - 绑定关系

---

## 4. 消息丢失原因

### 4.1 生产者到交换机

- 交换机名称错误
- 网络波动
- 配置未开启 `Confirm`

### 4.2 交换机到 Queue

- `routing key` 错误
- 队列未绑定
- 配置未开启 `Return`

### 4.3 Queue 到消费者

- 消费者监听错误
- 业务处理异常

---

## 5. 生产者消息可靠性保障

### 5.1 Confirm 机制

- 确保消息成功到达交换机
- 需要开启 `publisher-confirm-type`
- 通过 `ConfirmCallback` 获取 `ack` 和 `cause`
- 可根据结果进行失败补偿

### 5.2 Return 机制

- 确保消息成功路由到目标队列
- 消息到达交换机但未进入队列时触发
- 可获取：
  - 消息体
  - 交换机名
  - `routing key`
  - 失败原因

### 5.3 补偿方案

- 失败后可选择重发消息
- 也可持久化失败消息以便后续处理
- 需要记录和管理重试次数
- 根据失败原因决定补偿策略
- 避免无限重试

---

## 6. 消费者可靠性保障

### 6.1 手动应答 Manual Ack

- 自动应答存在消息丢失风险
- 消费成功后调用 `basicAck`
- 消费失败时调用 `basicNack` 或 `basicReject`

### 6.2 实现要点

- 监听器应答模式改为 `manual`
- 通过 `message.getMessageProperties().getDeliveryTag()` 获取 `deliveryTag`
- 成功后执行：

```java
channel.basicAck(deliveryTag, false);
